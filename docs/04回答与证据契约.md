# 找回视频与笔记草稿的回答及证据契约

> 状态：本轮后端实现的第一版契约。完整的“找回 → 选择视频 → 生成可复习笔记”前端流程与质量评测仍在产品计划中。

## 通用边界

- `session_id` 必须对应有效会话；`folder_ids` 是用户可访问的 B 站收藏夹 `media_id`。未指定收藏夹时只查该用户已入库的收藏夹，指定无权访问的收藏夹应拒绝，而不是扩大到全库。
- 后端决定可访问视频并准备证据，模型只根据传入的证据写作。回答中的 `[E1]` 等编号必须对应响应的 `sources[].evidence_id`；来源对象由后端生成，包含视频、可跳转链接、时间范围、内容来源和证据摘录。
- 字幕与 ASR 片段可以支持“视频说了什么”和时间跳转；仅标题、简介或 AI 摘要只能作为弱线索，不支持精确片段或完整笔记。没有证据时直接说明缺口，不把常识伪装成收藏视频内容。
- 现在的引用由提示词约束，尚未逐条自动校验模型生成的论点与证据。验收时必须人工核对。

## 找回视频 `task=find`

**回答格式**：`找到的收藏视频` 列表，每项给出视频标题、与问题相关的具体内容、对应的 `[E#]` 和片段时间（若有）；末尾给出 `范围与限制`，说明只有标题线索、无时间戳或没有可靠命中的情况。链接由 `sources` 提供，模型不能自行编造 BV 号或时间。

**证据要求**：候选来自当前会话和收藏夹范围内的向量命中；片段引文必须能在返回的证据摘录中找到。若仅凭标题/简介匹配，必须标成“仅元数据线索”，不能声称定位到了视频内片段。

## 生成笔记 `task=note`

**输入范围**：优先显式传 `video_bvids`（最多 3 条，必须属于当前选定收藏夹）。未传时，可在问题中给出 BV 号；若范围内只有一条视频也可直接生成。目标不明确时先要求用户指定视频，避免把整个收藏夹误写成单视频笔记。

**回答格式**：标题标明“笔记草稿”；依次写 `核心概览`、`按内容顺序整理的要点`、`步骤/例子/观点差异`（只写有证据的部分）、`证据与局限`。各关键事实或观点就近标注 `[E#]`。多视频笔记需保留观点归属，不能把不同视频的意见强行合并。

**证据要求**：仅用有时间轴的字幕或 ASR 文字稿生成。后端按时间顺序抽取带编号片段，并向模型提供本次片段数与总片段数；若篇幅限制导致只提供部分片段，后端固定在回答前显示覆盖提示，模型的标题与局限也应明确写“部分内容”，不得称为完整视频笔记。只有基本信息或没有文字稿时，返回缺少可靠笔记依据的提示。

## 第一版验收

固定同一数据快照，至少检查：跨收藏夹找回能否命中正确视频和时间、指定收藏夹能否限制结果、无权收藏夹与无效会话是否拒绝、只有基本信息的视频是否被错误引用、笔记中的关键点能否回到片段、部分覆盖是否明确提示。原始输入、响应、来源、人工判定和 badcase 原因保存在评测报告中，不预写质量提升数字。
