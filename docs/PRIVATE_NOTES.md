## 三、正式文档中的合理推断与补全

| 正式文档部分 | 推断/产品设计内容 | 为什么与已有架构相容 | 不应延伸成什么说法 |
| --- | --- | --- | --- |
| §1 用户与场景 | 大学生、初级开发者，复习/写代码时模糊找回，点击后实际学习使用 | 现有产品适合技术学习收藏夹，可由个人样本构造任务 | 不等于对广泛真实用户进行过访谈或长期留存验证 |
| §1 产品闭环 | “用户打开正确片段并用于学习”为成功 | 现有来源链接和时间跳转支持核对动作 | 不等于已采集真实点击转化和学习提升 |
| §2 成功指标 | VTSR、内容就绪率、@3 命中、证据支持、笔记覆盖、P50/P90、有效成本和护栏 | 接口、日志、视频来源和人工复核可组成评测链路 | 不等于项目已经有完整埋点仪表盘和实测基线 |
| §3 Agent 定位 | 受控单工作流，不使用多 Agent 自主讨论；按清单与内容需求分流 | 对应 README 所述的 FastAPI + SQLite/Chroma + 任务接口 | 不宣称原生 function calling、自动 Planner/Verifier 链 |
| §3/§4 双路由细节 | 清单偏 SQLite，内容偏 Chroma；一般问答模型有限路由、直答路径 | 旧自查文档有 `_route_with_llm` 等路径线索 | 未核验实际代码前不要保证每类自然语言都百分百命中该路径 |
| §3/§4 失败体验 | 分层错误提示、用户重选与更新、明确证据边界 | 现有入库更新、来源展示、异常降级提供界面/接口基础 | 不等于有成熟自动重试、队列调度、分布式容错 |
| §5 引用契约 | 强来源可支持片段级结论、弱来源只支持视频级线索 | README 明确不同来源证据强弱和有时间信息时跳转 | 不等于来源引用的所有关键陈述已通过人工一致性测评 |
| §6 评测规程 | 40 条、五维评分、双人独立复核、8/10 且双核心项 2 分、一票否决 | 可以通过固定题集、服务回放和人工检查完成 | 不等于已完成 40 条真实视频标注与独立双评 |
| §7 对比实验 | A/B 只变生成证据模板，固定检索证据和模型 | 可调整模型提示而不更改现有数据通路 | 不等于已有 40 对线上 A/B，也不等于示例数字真实发生 |
| §8 Badcase | B01–B03 由旧笔记声称存在构造回归；B04–B05 是对照风险案例 | 有范围校验、弱来源笔记门槛、有限上下文等技术对应点 | 不等于这些问题都发生过在真实用户或生产环境 |

| §9 效益陈述 | 更快找回、降低无证据回答风险、便于复习 | 来自链路设计和合理用户价值假设 | 不要声称实测节省 xx% 学习时间 |
| §10 下一步 | 章节化笔记、多轮指代、按需外部核验、凭据保护 | 属于在现有结构上的渐进扩展与风险治理 | 不要在简历里写成当前交付功能 |

## 五、面试前必须优先确认的五个推断点

1. **用户任务是否真实存在**：能否从自己的收藏记录/真实任务回放中拿出至少 3 个典型场景，展示用户输入、目标视频、点开来源后的下一步？“学生和初级开发者”的代表性是定位假设，不是既有调研结论。
2. **内容证据分布与可跳转性**：实际入库视频中，字幕、ASR、平台 AI 摘要和纯元数据各占多少？时间戳跳转是否能定位到正确片段？这是找回与笔记承诺的天花板。
3. **任务路由和权限过滤的代码落点**：一般问答究竟怎样路由到数据库/向量/直接回答？BV 集合是否确实做了前置与后置过滤？多用户、过期会话、显式指定越界收藏夹的断言结果是否可重跑？
4. **40 题评测与 A/B 示例是否替换为真实回放**：40 题究竟是设计目标还是已标注跑分？是否保存了同题模型输出、来源、人工评分、耗时与 Token 账单？`63%→73%` 和成本数在没有证据前只能称“演算示例”。
5. **亲自完成的迭代范围与时间线**：15/12 长稿覆盖提示、仅元数据笔记拒绝、跨用户片段过滤中，哪些有 Git diff、测试报告和修复前后截图？收藏夹整理确认、自动更新与错误处理有哪些实际上手验证？面试叙事应与个人负责内容一致。

## 六、最短自查与证据准备清单

- 拿到真实仓库后，打开上述 `app/`、`frontend/`、`test/` 文件核对函数、参数名和断言，不以旧文档替代源码。
- 从真实收藏里抽取 15–20 条视频，按内容来源分类，标注至少 10 个可点开的 BV/时间片段；再扩成 40 条正式题集。
- 固定 `.env` 中的模型与 Embedding 版本、收藏夹权限快照和索引版本；保存每次回放的原文、来源、人工评价和计费口径。
- 做一次真正的 A/B 成对实验：同题、同片段、同模型，仅修改证据契约；报告成功数、支持结论数、首字/总耗时及单位成本，记录每个 badcase。
- 简历只保留你能现场打开证据说明的数字；若引用方案性数字，明确说“评测设计”“构造回归”“示例演算”，而非真实用户效果。
